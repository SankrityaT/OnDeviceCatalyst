**Honest summary.** D8 is the only one of the eight baseline defects that is
*fully* characterized by executable code on the measured surface (`SFC-B`).
D1, D2, and D3 are genuinely *partially* covered: the half that needs no
ready model instance and no real generation is executed today; the other
half needs `R3` (real inference on a physical device) and is written,
skipping, per Q1's disposition below. D4, D5, D6, and D7 are packaging or
repository facts, not runtime behavior; they are pinned by the checker
(`--packaging`), not by XCTest, and the spec's own "## Tests" table marks
them "No" or "Partly" for exactly this reason -- a suite that claimed
otherwise would be overclaiming.

## Q1 disposition: `r3_disposition: specified-unexecuted`

`xcrun devicectl list devices` on the implementation host lists one paired
device (an iPhone 16 Pro Max), so a device is *physically present*. This
ticket's scope, set explicitly by the implementing instruction and consistent
with the spec's own Q3 analysis, is: **do not attempt device execution.**
Device deployment for a package-only, no-`.xcodeproj` test bundle is
unmeasured design (Q3, below) and is allocated to ODC-0021
("Establish a physical-device execution surface, including signing,
provisioning and deployment"), not to this ticket.

All five `R3` cases (`C-D2-3`, `C-D2-4`, `C-D3-3`, `C-D1-3`, `X-GEN-1`) are
written and call `requireDevice()`/`requireModelAsset()`, so they skip with
`SKIP[requires-device]` on `SFC-B` today. Per the spec's Q1, this is the
second, non-weakened outcome: `R0`, `R1`, and `R2` are executed; `R3` becomes
an obligation on whichever of ODC-0010, ODC-0011, or ODC-0012 first needs it.

```
r3_disposition: specified-unexecuted
```

## Q3 disposition: `device_execution_disposition: unmeasured-deferred`

Not measured by this ticket. `scripts/run-characterization.sh --surface
device` is a declared but intentionally unimplemented entry point: invoking
it fails loudly with a `harness-defect` message naming Q3, rather than
silently doing nothing. No code-signing, provisioning, entitlements, or
device-deployment tool is implemented here.

```
device_execution_disposition: unmeasured-deferred
```

## Q2 disposition (informational; not gated by A17/A18)

Not observed during implementation: the host's Xcode 26 Metal Toolchain
component was not downloaded (spec N7's finding stands), so whether an
Xcode-built consumer's `MetalComputeEngine` failure differs in message from
the SwiftPM-built one remains unmeasured. `C-D5-4` accordingly asserts only
that construction throws a `CatalystError`, not which of the two possible
messages is produced. Owner: ODC-0014.
